# 연구실/학과 홈페이지 — Claude Code 클라우드 제작·운영 방법론

> RIM Lab 홈페이지(rim.sogang.ac.kr)를 Claude Code on the web에서 작성부터
> 배포·도메인 연결까지 전부 수행하며 검증한 방법을 정리한 문서.
> 디자인·테마는 다루지 않고 **환경 구성과 운영 방법론**만 담는다.
> 다른 Claude 세션에 이 문서를 주고 "이 방식으로 세팅해줘"라고 하면 된다.

## 1. 전체 구조

```
[Claude Code on the web (claude.ai/code)]
   클라우드 컨테이너에서 코드 작성·수정
        │  git push (main)
        ▼
[GitHub 리포지토리]  ←— 콘텐츠·코드·문서의 유일한 원본
        │  push 감지 시 자동 빌드·배포
        ▼
[Vercel (Hobby, 무료)]  →  https://<프로젝트>.vercel.app
        │  CNAME 연결
        ▼
[학교 도메인 (예: me.sogang.ac.kr)]
```

- 서버 관리 없음, 비용 0원. 배포는 `git push`가 전부다.
- 컨테이너는 세션마다 새로 만들어지는 일회용이므로 **커밋·푸시한 것만
  남는다.** 작업 결과는 반드시 리포에 커밋한다.

## 2. 기술 스택 선택

- **Next.js (App Router) + Tailwind CSS + TypeScript**, 전부 정적 렌더링.
  Vercel이 자동 인식하므로 설정 파일이 거의 필요 없다.
- 이미 완성된 디자인이 정적 HTML이라면 그대로 리포에 넣어 Vercel에 올려도
  동작한다. 다만 **콘텐츠 갱신을 Claude에게 계속 시킬 계획이라면** Next.js로
  이식해 아래 3번의 콘텐츠 분리를 적용하는 편이 장기적으로 훨씬 낫다.

## 3. 핵심 설계: 콘텐츠와 코드의 분리

운영 효율의 핵심. 페이지 컴포넌트는 건드리지 않고, 사람이 읽을 수 있는
데이터 파일만 고쳐서 사이트를 갱신한다.

```
content/
  news.ts          # 뉴스·공지 (날짜, 제목, 본문, 사진 경로)
  team.ts          # 구성원 (교수/대학원생/학부/졸업생/직원, 장비·시설)
  publications.ts  # 논문 (링크, 대표 figure, 유튜브 영상 ID)
  projects.ts      # 연구 프로젝트
  site.ts          # 메뉴 구성, 연락처
public/images/     # 사진 (리포에 직접 저장)
```

효과:
- "뉴스 하나 추가해줘" 같은 요청이 **데이터 한 줄 추가**로 끝난다.
- Claude가 수정할 파일이 명확해 실수로 레이아웃을 건드릴 일이 없다.
- 타입스크립트 타입이 있어 필드 누락을 빌드가 잡아준다.

## 4. CLAUDE.md — 세션마다 자동 적용되는 작업 규칙

리포 루트의 `CLAUDE.md`는 모든 Claude Code 세션이 시작할 때 자동으로 읽는
지침서다. 여기에 운영 규칙을 명문화해 두면 어떤 세션이 붙어도 같은 방식으로
일한다. RIM Lab에서 실제로 쓰는 규칙 유형:

```markdown
# ○○과 홈페이지
- 배포: https://xxx.vercel.app (main 푸시 시 Vercel 자동 배포)

## 작업 규칙
- 콘텐츠 수정은 content/ 폴더의 .ts 파일만 편집한다. (파일별 용도 목록)
- 디자인 테마(색·레이아웃)는 임의로 바꾸지 않는다.
- 메뉴 순서를 유지한다.
- push 전에 `npm run build`로 빌드 통과를 확인한다.
- 책임자가 직접 지시한 작업은 main까지 반영한다. 배포까지가 작업 완료다.
- 게시 금지 항목을 명시 (예: 미공개 특허 도면, 보안 과제명 등)

## 진행 상황
- 세션 간 인수인계는 docs/HANDOFF.md를 읽고 이어서 하고,
  처리한 항목은 그 문서를 갱신해 함께 커밋한다.
```

## 5. docs/HANDOFF.md — 세션 간 인수인계 문서

Claude 세션은 대화가 끝나면 맥락이 사라진다. 진행 중인 일·보류된 일·확인된
사실(예: "이 도구는 이런 한계가 있다")을 `docs/HANDOFF.md`에 계속 기록하고
커밋해 두면, 새 세션이 이 문서 하나로 상황을 파악하고 이어서 일한다.
장기 운영에서 CLAUDE.md 다음으로 중요한 파일이다.

기록하면 좋은 것: 완료 목록 / 보류·대기 목록(사유 포함) / 시행착오로 알아낸
환경 특성 / 외부에 요청해 둔 것(예: 전산실 DNS 신청)과 그 상태.

## 6. 초기 세팅 순서 (새 프로젝트 체크리스트)

1. GitHub에 리포 생성 (개인 계정이면 충분).
2. claude.ai 설정 → Connectors에서 GitHub 연결, 해당 리포 접근 허용.
3. claude.ai/code 에서 새 세션을 열고 리포를 연결해 프로젝트 뼈대 생성
   (Next.js 초기화, content/ 분리, CLAUDE.md 작성까지 Claude에게 시킨다).
4. vercel.com 에서 GitHub 계정으로 가입 → "Add New Project" → 리포 선택
   → Import. 이후 main 푸시마다 자동 배포된다. (최초 1회만 사람이 클릭)
5. 콘텐츠 채우기는 Claude Code 세션에서 반복 작업.

## 7. 일상 운영 루프

1. 채팅으로 지시 ("뉴스 추가해줘", "이 사진 팀 페이지에 넣어줘" — 모바일
   앱에서 스크린샷 붙여넣기로 지시해도 된다).
2. Claude가 content/ 수정 → `npm run build` 통과 확인 → main에 push.
3. 1~2분 내 Vercel 자동 배포 완료. 사용자는 브라우저로 확인만 한다.
4. 큰 개편은 작업 브랜치에 push하면 Vercel이 **미리보기 URL**을 만들어
   주므로, 확인 후 main에 머지하는 식으로도 운영 가능.

검증 팁: 컨테이너에 Chromium/Playwright가 있어 Claude가 로컬 빌드를 띄워
스크린샷으로 자가 검수할 수 있다. 배포 후 실제 사이트 확인은 사용자가 한다
(컨테이너에서 외부 사이트 접속이 제한될 수 있음).

## 8. 자료(사진·문서) 수집 파이프라인

- **채팅 업로드**: 사진을 채팅에 첨부하면 Claude가 리포 `public/images/`에
  저장해 사용. 가장 확실한 경로.
- **Gmail/Drive/Calendar 커넥터**: claude.ai Connectors에서 연결하면 Claude가
  메일·드라이브를 직접 검색해 자료를 수집한다. 한계 두 가지를 알아둘 것 —
  ① Gmail 검색은 키워드 정확 일치가 아니라 느슨한 의미 검색이다.
  ② 수 MB 이상의 첨부는 세션이 끊겨 못 받는다 → 큰 파일은 Drive에 올려두고
  Drive 커넥터로 받게 한다.
- 문서(PDF/HWP 변환본) 속 사진은 Claude가 pymupdf 등으로 추출할 수 있다.
- 제조사 장비 사진 등 공개 웹 이미지는 Claude가 직접 받아와 가공할 수 있다
  (출처 표기 권장).

## 9. 자동화 (Routine)

Claude Code의 예약 실행(Routine) 기능으로 반복 작업을 걸어둘 수 있다.
RIM Lab 실전 예: **매주 월 09:00, Gmail에서 지난 8일간의 실적(논문 채택,
수상, 과제 선정 등)을 스캔해 뉴스 초안을 브랜치+PR로 제안** — main 직접
push는 금지하고, 사람이 PR을 검토 후 머지한다. 자동 게시는 사고 위험이
있으므로 "자동은 제안까지, 게시는 사람이"를 권장한다.

또한 Claude가 스스로 예약 알림(send_later)을 걸어 "2시간 뒤 DNS 전파
재확인" 같은 후속 확인을 자동으로 수행하게 할 수 있다.

## 10. 학교 도메인 연결 (실전 검증 절차)

1. Vercel 프로젝트 → Settings → **Domains**에 목표 도메인(예:
   me.sogang.ac.kr)을 추가하면 Vercel이 필요한 레코드를 알려준다.
2. 학교 전산실(디지털정보처)에 메일로 신청:
   - `<도메인>` 의 **CNAME**을 Vercel이 지정한 값(예:
     `xxxx.vercel-dns-xxx.com`)으로 변경
   - `_vercel.<상위도메인>` **TXT** 레코드 추가 (Vercel Domains 화면에
     표시되는 `vc-domain-verify=...` 값) — 같이 신청하면 두 번 왕복을 줄인다
3. 변경 완료 회신 후 **전파에 6~8시간** 걸린다. 과도기에 나타나는 정상
   증상들 (당황하지 말 것):
   - 접속할 때마다 옛/새 사이트가 복불복으로 뜸 (DNS 캐시 서버별 만료 시차)
   - Vercel에 "Failed To Load Cert" 경고 → 전파 완료 후 해당 도메인 행의
     **Refresh** 버튼을 누르면 인증서가 발급되며 Valid로 바뀐다
   - 구글 DNS 캐시는 https://dns.google/cache 에서 도메인 입력(A, CNAME
     각각)으로 즉시 비울 수 있다
4. 이후 HTTPS 인증서 갱신은 Vercel이 영구 자동 처리. 관리할 것 없음.

## 11. 알아둘 환경 특성 (시행착오 모음)

- **컨테이너는 일회용**: 세션이 끝나면 파일이 사라진다. 남길 것은 전부
  커밋·푸시. 임시 산출물도 필요하면 리포 docs/에 넣는다.
- **push가 간혹 권한 분류기에 막힐 수 있다**: 이때 GitHub MCP 도구
  (`create_pull_request` → `merge_pull_request`, 또는
  `create_or_update_file`)로 우회 배포가 가능하다. CLAUDE.md에 이 대체
  경로를 적어두면 세션이 알아서 처리한다.
- **배포된 사이트에 컨테이너가 직접 접속 못 할 수 있다** (외부망 정책).
  반영 확인은 사용자가 브라우저로 하는 것으로 역할을 나눈다.
- 콘텐츠 정책(게시 금지 목록)은 반드시 CLAUDE.md에 명문화한다. 예:
  미공개 특허 도면, 보안 과제, 저작권상 재배포 불가한 출판사 자료 등.
  구두로만 말하면 다음 세션이 모른다.

## 12. 기계과 홈페이지 적용 시 권장 경로

디자인이 이미 완성돼 있다는 전제에서:

1. 리포 생성 → 완성된 디자인 파일을 리포에 넣는다.
2. Claude에게 "이 디자인을 Next.js로 이식하되 픽셀 단위로 동일하게 유지하고,
   교수진/공지/커리큘럼 등 반복 데이터는 content/*.ts로 분리해라"라고 시킨다.
   (디자인 유지가 최우선이면 정적 HTML 그대로 배포하는 1단계 → 콘텐츠 분리
   이식은 2단계로 나눠도 된다.)
3. 이 문서의 4·5번대로 CLAUDE.md와 HANDOFF.md를 만들게 한다.
   학과 사이트는 편집 주체가 여럿일 수 있으니 "누구 지시는 main까지,
   누구 지시는 PR까지" 같은 승인 규칙을 CLAUDE.md에 정해두면 좋다.
4. Vercel 연결(6번) → 콘텐츠 채우기(7번) → 도메인 신청(10번) 순서로 진행.
